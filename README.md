# recruit-cleaner · 协会招新报名数据清洗小工具

每年招新都会收到几百份报名表（问卷导出的 CSV）。这个工具负责把原始报名表
**读进来 → 挑出填错的/重复的 → 统计志愿分布 → 导出干净数据**。

设计原则：**只读原文件，绝不原地修改**。所有产出都写到 `output/` 目录。

## 输入数据

CSV 表头约定为以下 6 列（顺序不限，列名需一致）：

| 列名 | 说明 |
| --- | --- |
| 姓名 | |
| 学号 | 应为纯数字 |
| 邮箱 | 应为 `学号@smbu.edu.cn` |
| 志愿1 | 第一志愿部门 |
| 志愿2 | 第二志愿部门（可空） |
| 推荐人 | 可空 |

仓库内置一份样例数据 `data/sample_recruits.csv`（43 行），
里面刻意埋了各种边界情况（非法学号、邮箱错配、域名写错、空值、完全重复行、
同学号重复报名等），方便直接跑起来看效果。

## 快速开始

零第三方依赖，只要有 Python 3.9+（用到 `dict`/`list` 的泛型注解，3.9 起支持）：

```bash
git clone <你的仓库地址>
cd recruit-cleaner

python main.py overview     # 需求 1：读入与概览
python main.py validate     # 需求 2：校验与清洗
python main.py stats        # 需求 3：志愿统计
python main.py export       # 需求 3：导出干净数据
python main.py all          # 一条龙跑完上面几步
```

不传路径时默认读仓库自带的 `data/sample_recruits.csv`，所以 clone 下来**不用准备数据就能跑**。
换成自己的报名表：

```bash
python main.py all data/2026秋招新报名.csv
```

Windows 上如果 `python` 不是 3.x，请用 `py -3 main.py ...` 或 `python3 main.py ...`。

所有产出都写到 `output/` 目录（已 gitignore），**原文件不会被改动**。

## 需求 1：读入与概览

```bash
python main.py overview
```

打印三件事：一共多少行、每列有多少个空值、有没有完全重复的行。

```
========================================================
 数据概览
========================================================
输入文件 : data\sample_recruits.csv
数据行数 : 43 行（不含表头）
统计列数 : 6 列

【每列空值】空值 = 空字符串或只有空白字符
列名    空值数  空值占比
------------------------
姓名         1      2.3%
学号         1      2.3%
邮箱         2      4.7%
志愿1        1      2.3%
志愿2       20     46.5%
推荐人      27     62.8%
合计空单元格：52 个

【完全重复的行】
发现 2 组完全重复的行，共 2 行属于重复出现：
  · 第 42 行 与 第 1 行 完全相同
  · 第 17 行 与 第 16 行 完全相同
```

实现要点：

- 用 `utf-8-sig` 读文件，自动吃掉问卷导出常见的 BOM，避免第一列表头变成 `\ufeff姓名`。
- "完全重复"比较的是 strip 之后的所有字段，所以 `2023010135@smbu.edu.cn `（尾部多一个空格）
  不会因为是脏数据以外的东西被误判；反过来 ` 2023010136 ` 这样的学号也不会被当成另一条记录。
- "行号"一律指源文件中的行号（表头算第 1 行），方便直接跳到 Excel 里对应位置核对。

### 已明确的边界假设

- **空值的定义**：空字符串、或 strip 后为空（只有空格/制表符/全角空格）都算空值。
- **编码**：默认按 UTF-8（带不带 BOM 都行）读取。如果手上是 GBK/GB2312 的老导出文件，
  加 `--encoding gbk`。

## 需求 2：校验与清洗

```bash
python main.py validate                  # 默认不校验学号位数
python main.py validate --id-length 10   # 若确认学号统一 10 位，开启位数校验
```

规则：

| 规则 | 说明 |
| --- | --- |
| 学号 = 纯数字 | 只认 ASCII `0-9`。全角 `２０２３`、阿拉伯-印度数字 `٢٠٢٣` 一律算错（`str.isdigit()` 会误放行，这里额外要求 `isascii()`） |
| 邮箱 = `学号@smbu.edu.cn` | 域名大小写不敏感（`@SMBU.EDU.CN` 算对）；域名不对、前缀与学号对不上，都算填错 |
| 同一学号出现两次 | 判为重复报名，**只保留首次出现的那条** |
| 整行完全重复 | 单独再标一次，便于区分"误提交两次"和"同一个人又报了一次（内容不同）" |

**原文件不会被改动**，有问题的行单独导出到 `output/issues.csv`，每行都写明判错理由：

```
数据行号,源文件行号,姓名,学号,邮箱,志愿1,志愿2,推荐人,严重级别,问题代码,问题说明
11,12,徐晶,20230101AB,20230101AB@smbu.edu.cn,外联部,,,ERROR,E002,[E002] 学号必须是纯数字，实际填写为「20230101AB」
17,18,郭强,2023010116,2023010116@smbu.edu.cn,技术部,,李娜,ERROR,E007;E008,[E007] 学号 2023010116 重复报名，首次出现在第 16 行（只保留首次那条） | [E008] 整行内容与第 16 行完全一致，疑似重复提交
```

问题代码表（`E` = 错误，会从干净数据里剔除；`W` = 提醒，保留但需人工补填）：

| 代码 | 级别 | 含义 |
| --- | --- | --- |
| E001 | 错误 | 学号为空 |
| E002 | 错误 | 学号不是纯数字 |
| E003 | 错误 | 学号位数不符（仅 `--id-length` 开启时校验） |
| E004 | 错误 | 邮箱为空 |
| E005 | 错误 | 邮箱域名或格式错误 |
| E006 | 错误 | 邮箱与学号不匹配 |
| E007 | 错误 | 学号重复报名 |
| E008 | 错误 | 整行完全重复 |
| W101 | 提醒 | 姓名为空 |
| W102 | 提醒 | 第一志愿为空 |

### 已明确的边界假设

- **学号位数**：需求只要求"纯数字"，没说几位，所以**默认不校验位数**。
  确认了就加 `--id-length 10`，此时会多报一类 `E003`。样例数据是 10 位。
- **邮箱大小写**：域名按大小写不敏感处理（`casefold` 比较），但不会帮你改写原值。
- **重复保留策略**：同一学号保留**首次**出现的那条。理由是首次通常是最完整的一次填写；
  如果你更想保留"最后一次"（比如允许改志愿），可以改 `_find_id_duplicates`，
  目前没有做成开关——有需要再说。
- **提醒级为什么不剔除**：姓名为空、第一志愿为空不影响去重和身份校验，
  直接删会丢人，所以保留进干净数据并在问题清单里点名，交给人工补。
- **脏空格不算错**：学号 ` 2023010136 `、邮箱 `2023010135@smbu.edu.cn ` 这种前后空格，
  strip 后合法就放行，不会塞进问题清单。

## 需求 3：统计与导出

```bash
python main.py stats     # 志愿统计 + 导出汇总表
python main.py export    # 导出清洗后的干净数据
python main.py all       # 概览 → 校验 → 统计 → 导出，一次跑完
```

```
========================================================
 志愿统计（基于清洗后的数据）
========================================================
原始数据 : 43 行
清洗后   : 33 行

【第一志愿分组统计】共 6 个部门
第一志愿   人数     占比
------------------------
技术部        9    27.3%
宣传部        7    21.2%
策划部        7    21.2%
外联部        5    15.2%
秘书处        4    12.1%
(未填)        1     3.0%
合计         33   100.0%

【志愿填写情况】
  两个志愿都填了 :   18 人  (54.5%)
  只填了一个志愿 :   15 人  (45.5%)
  两个都没填     :    0 人  (0.0%)
```

产出文件（`output/` 目录，已 gitignore）：

| 文件 | 内容 |
| --- | --- |
| `issues.csv` | 问题清单（需求 2）：每行一个问题记录 + 判错理由 |
| `stats_first_choice.csv` | 第一志愿汇总表：第一志愿 / 人数 / 占比 |
| `stats_choice_fill.csv` | 志愿填写情况：填写情况 / 人数 / 占比 |
| `clean.csv` | 清洗后的干净数据，列顺序与原表一致 |

`clean.csv` 可直接导入飞书/腾讯文档/Excel 继续排面试。

### 已明确的边界假设

- **统计口径是清洗后的数据**，不是原始行数。重复报名如果不先去重，
  第一志愿人数会被同一个人重复计入。
- **第一志愿为空**的人不会从统计里消失，而是单独归到 `(未填)` 一组，
  避免"33 行数据、分组加起来只有 32"这种对不上账的情况。
- **"只填了一个"包含只填了第二志愿的人**（第一志愿空、第二志愿非空）。
  三个口径（都填 / 只填一个 / 都没填）相加恒等于清洗后总行数。
- **干净数据只做 strip，不改写大小写**。邮箱 `@SMBU.edu.cn` 保持原样写回，
  方便跟问题清单对照；大小写不影响邮件投递，所以没必要动。
- **排序**：人数降序；人数相同时按部门名升序，保证每次跑出来的表一模一样，
  方便跟上一届对比。

## 项目结构

```
recruit-cleaner/
├── main.py                     # 命令行入口：python main.py <子命令>
├── recruit_clean/
│   ├── loader.py               # 需求 1：读入 CSV（BOM / 脏空格处理）
│   ├── overview.py             # 需求 1：行数、空值、完全重复行
│   ├── validator.py            # 需求 2：学号 / 邮箱 / 重复报名校验
│   ├── stats.py                # 需求 3：志愿统计
│   ├── exporter.py             # 导出：问题清单 / 汇总表 / 干净数据
│   ├── text.py                 # 终端表格排版（中文宽度对齐）
│   └── cli.py                  # 子命令解析
├── data/sample_recruits.csv    # 样例数据（43 行，含各类边界情况）
├── tests/                      # 单元测试（22 条）
└── output/                     # 运行产物，不入库
```

数据流：`读入 loader → 校验 validator → 干净数据 → 统计 stats → 导出 exporter`。
每个环节都不写回原文件，`output/issues.csv` 记录被剔除的原因，`output/clean.csv`
可直接丢进飞书或腾讯文档继续排面试。

## 已知限制

- 不做学院 DNS 校验，邮箱只读格式与学号是否对应，不验证邮箱真实存在。
- 学号位数默认不校验（见上文假设），需要时加 `--id-length`。
- 重复报名固定保留首次出现，没有做成可配置项。
